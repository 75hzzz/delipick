# 네이버 경로 갱신 설정 복구

이 문서는 10월 20일 설정 복구 당시의 기록입니다. 10월 25일에는 실패 시 20분을 저장하던 동작을 수정해 기존 값과 갱신 시각을 보존하도록 했고, 첫 갱신도 API 준비를 막지 않는 백그라운드 작업으로 바꿨습니다. 최신 내용은 `../release_audit/REPORT.md`와 루트 README를 참고하세요.

2026년 10월 20일 확인 결과, 기존 `update_delivery.py`와 API 시작 이벤트는 남아 있었지만 Docker Compose에서 `ENABLE_DELIVERY_WORKER`를 false로 고정했고 루트 환경 파일에 네이버 키 항목이 누락되어 있었다.

루트 `.env.example`과 현재 로컬 `.env`에 빈 키 항목 및 기본 비활성화 옵션을 추가했다. 기존 DB 비밀번호와 OpenAI 설정은 변경하지 않았다. Compose API 서비스만 활성화 플래그와 네이버 키를 전달받도록 수정했고 초기화 서비스는 계속 비활성화한다. 가상 샘플용 start.ps1 -Demo에서도 갱신 작업은 끈다. 기존 추천·배달 계산 Python 모듈 자체는 변경하지 않았다.

활성화는 루트 `.env`에 올바른 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`을 넣고 `ENABLE_DELIVERY_WORKER=true`로 바꾼 뒤 Docker Desktop과 start.ps1을 실행하면 된다. 서버 시작 때 한 번 갱신하고 이후 프로세스가 켜져 있는 동안 60분마다 반복한다. 음식점 좌표가 없으면 해당 항목을 건너뛴다.

현재 출발점은 코드의 고정 좌표다. 네이버의 경로 이동시간은 restaurants.delivery_time에 저장되고 조리시간과 혼잡도 시뮬레이션은 별도로 더해진다. 키가 없거나 API 오류가 나면 기존 함수가 반환한 20분도 저장될 수 있으므로 키와 권한 확인 전에는 활성화하지 않는 것이 안전하다. 재시작마다 호출되며 API 프로세스를 여러 개로 늘리면 중복 스케줄 실행을 별도로 막아야 한다.

검증은 Compose 설정 파싱으로 키·활성화 값 전달 및 초기화 서비스의 비활성화를 확인했고, 실제 네트워크·DB 갱신을 하지 않는 모의 테스트 3개가 통과했다. 결과는 naver_worker_tests.xml에 있다. 당시 Docker Desktop 엔진이 실행 중이지 않아 새 이미지 빌드와 컨테이너 재기동은 검증하지 못했다. 실제 네이버 인증·요금·응답 성공이나 배달시간 갱신을 검증한 것은 아니다.
