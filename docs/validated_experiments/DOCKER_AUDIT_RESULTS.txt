# Docker 검증 결과

검증일 2026년 10월 19일

## 공유 가상 데이터 실험

실제로 Docker MySQL과 Qdrant를 연결했다. 가상 음식점 28개·메뉴 224개·가상 리뷰 28개이며, 1536차원 실제 임베딩을 미리 생성한 데이터다. 아래 수치는 실제 수집 데이터나 전국 데이터 결과가 아니다.

통합 테스트는 44개 중 실패 0개, 오류 0개, 건너뜀 0개였다.

검색·재정렬 구간 평균은 before **114.73ms**, after **62.16ms**였다. 각 버전 12회 측정이며 예시 자연어 네 개에 각각 워밍업 1회와 측정 3회를 사용했다. 약 1.85배 차이지만 소규모·짧은 반복이므로 일반적인 배속 보장은 아니다. 외부 LLM 및 사용자 임베딩 API 대기시간은 제외했다.

## 결과 재현 조합 검사

총 **576개 중 576개 일치**했다. 기준 결과가 있는 조합은 432개였고 새롭게 빈 결과가 된 조합은 0개였다.

예시 질의 4개 × 사용자 유형 3개 × 맛 프로필 3개 × 요청 개수 4개 × UI 필터 조합 4개다. 요청 개수는 1·5·10·20이고, UI 조건은 전체·한식 1만 원 이하·중식 및 일식 1만5천 원 이하·카페 5천 원 이하로 구성했다.

같은 조건을 적용해 후보 전체를 계산하는 SQL 기준과 Qdrant 경로의 음식점 ID·메뉴 ID 순서 및 최종 점수를 비교했다. 점수 오차 허용값은 1e-9다. 이 검사는 작은 집합에서도 Qdrant를 실제 사용하도록 우회 임계값을 일시적으로 0으로 설정했다.

576개는 576개 독립 자연어 문장이 아니다. 네 자연어 예시의 파라미터 조합이고, 사용자 만족도나 의미 이해 정확도 검증도 아니다.

## 실제 HTTP 동시 요청

기존 Docker API의 `/recommendations`에 실제 HTTP 요청을 보냈다. 각 동시성 수준마다 32개 요청을 보냈고 외부 API 결과는 replay했다. 다음 지연은 네트워크·웹 서버 처리도 포함한다. before와의 동시 부하 비교는 실시하지 않았다.

| 동시 요청 수 | 정상 200 및 5개 반환 | 평균 ms | p95 ms | 초당 완료 요청 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 32/32 | 73.04 | 222.58 | 13.68 |
| 4 | 32/32 | 191.21 | 567.30 | 18.74 |
| 8 | 32/32 | 348.42 | 1107.28 | 17.57 |

동시 요청 8개에서는 평균과 p95가 증가했다. 따라서 ‘동시 사용자가 늘어나도 항상 같은 속도’라고 설명하면 안 된다. 단일 PC·32개 요청의 짧은 실행이므로 최대 처리량, 장시간 안정성, 메모리 누수, 실서비스 SLA를 입증하지 않는다.

## 실제 수집 데이터 Docker 재측정

공유 Git 저장소 밖에 실제 수집 데이터 복사본을 두고 별도 MySQL·Qdrant Docker 프로젝트에서 측정했다. 원문 리뷰와 비밀번호는 이 보고서에 포함하지 않는다. 10배·30배는 동일 데이터의 ID 오프셋 복제다.

| 규모 | 경로 | 표본 | 평균 ms | p95 ms | 평균 상세 메뉴 행 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 1 | before | 9 | 366.69 | 416.83 | 953.00 |
| 1 | sql | 9 | 26.37 | 38.50 | 34.33 |
| 1 | qdrant | 9 | 28.31 | 37.11 | 34.33 |
| 10 | before | 9 | 6341.55 | 6759.91 | 9530.00 |
| 10 | sql | 9 | 182.11 | 341.87 | 343.33 |
| 10 | qdrant | 9 | 234.60 | 365.32 | 266.67 |
| 30 | before | 9 | 23166.54 | 24502.00 | 28590.00 |
| 30 | sql | 9 | 927.24 | 1598.00 | 1030.00 |
| 30 | qdrant | 9 | 672.86 | 927.79 | 423.33 |

국물·면·혼자 먹기 세 질의별 워밍업 1회 및 측정 3회다. 같은 분석·임베딩 응답을 재사용하고 음식점별 ETA를 고정했다. 워밍업 이후 경로별 실행 순서를 섞었다. before는 기존 계산, sql은 동일 필터 후 전체 계산, qdrant는 최종 개선 경로다. 외부 API 대기시간과 데이터 준비·인덱스 생성 시간은 제외했다.

before도 같은 Docker DB와 인덱스를 사용한다. 따라서 인덱스 추가만의 효과를 분리한 실험은 아니다. 1배의 세 질의는 후보 200개 이하라 qdrant 설정 경로에서도 Qdrant를 우회한다. 10배 등에서 sql이 qdrant보다 빠를 수도 있으며, 작은 후보 집합에 벡터 엔진이 무조건 유리한 것은 아니다.

실제 데이터의 Docker 결과 재현 검사는 336개 중 순서 일치 336개, 새 빈 결과 0개, ID가 같은 결과의 최대 점수 차이 0이었다. 기준은 같은 조건의 SQL 전체 계산이다.

작업 PC CPU는 13th Gen Intel(R) Core(TM) i7-13700KF, 논리 프로세서 24개이며 Docker에는 CPU 24개와 메모리 약 15.52GiB가 보인다. 기존 공유 데모 서비스는 켜 둔 상태였지만 원본 데이터 순차 측정 중 부하 요청을 보내지는 않았다. Windows MySQL은 읽기 전용 내보내기에만 사용하고 시간 측정에서는 Docker MySQL을 사용했다.

별도 조건 검사에서는 반환 1584개 중 인식한 태그·제외 단어·가격·UI 카테고리 위반이 0개였다. 실제 음식의 적합성이나 LLM이 누락한 조건까지 검증한 것은 아니다.

이미지 안의 핵심 코드 12개 체크섬, DB 행 수, Qdrant 포인트 수·1536차원 설정, 기록된 질의 36개를 대조했다. 세 규모의 좁은 요청 측정 27개 중 27개에서 전체 계산과 순위별 점수가 1e-6 이내로 일치했다. 복제 데이터는 동점 ID가 달라질 수 있다.

실행 환경은 Docker Python 3.12.15, MySQL 8.4.11, Qdrant 1.19.2, x86_64다.

원본 규모에서 Qdrant 메뉴 벡터는 1104개 메뉴, 유효한 리뷰 벡터는 311개 메뉴에 등록되어 있었다. 리뷰 원문 행 수와 메뉴별 리뷰 벡터 커버리지는 다르며, 이 테스트가 리뷰 없는 메뉴의 이용 경험까지 검증한 것은 아니다.

30배 넓은 요청 추가 검사에서는 질의 6개 × 유형 3개인 18개 중 결과 개수 일치 18개, 순위별 메뉴명 일치 18개, 순위별 점수 1e-6 이내 일치 18개였다. 최대 순위별 점수 차이는 0.0이었다.

넓은 질의는 일반 추천·저렴한 음식·따뜻한 음식·새콤한 음식·빠른 수령·함께 나눠 먹기다. 질의별 한 번의 회귀 검사이며 이전 실험에도 사용한 질의다. 독립적인 미관측 테스트나 반복 측정 속도 통계로 설명하지 않는다.

## 근거와 재실행

- `docker_tests.xml`, `docker_validation.json`: 통합 테스트 및 이번 검색 시간 집계
- `docker_demo_benchmark.json`: 검색 시간 원시 측정값
- `docker_extended_quality.json`: 576개 조합별 비교 결과
- `docker_http_load.json`: 동시 요청별 HTTP 결과와 지연
- `code_change_inventory.json`: 변경 파일·함수 줄 번호·코드 체크섬
- `recommendation_changes.diff`: 실제 핵심 코드의 전체 차이

- `docker_original_data_audit.json`: 실제 데이터 Docker 성능·결과·벡터 커버리지·HTTP 부하 집계. 실제 데이터 실험을 완료했을 때 생성한다. 원문 리뷰와 비밀번호는 제외한다.

```powershell
docker compose exec -T api python -m pytest deployment/test_stack.py -q -p no:cacheprovider
docker compose exec -T api python -m deployment.benchmark --repeats 3
python tools/extended_validation.py
```

공유 설정을 기본값으로 실행한 환경 기준이다. 다른 PC나 새 데이터에서 수치는 달라질 수 있다. 실제 서비스의 LLM 지연·요금·동기화·안전 조건·보안 운영까지 모두 검증한 것은 아니다.
