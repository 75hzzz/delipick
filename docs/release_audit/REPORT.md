# GitHub 공유 전 최종 검증

검증일: 2026-10-25. 대상: `merge-test`의 `c0e405d` 기반 통합본. 배포 브랜치: `test/qdrant-docker`.

## 범위와 결과

기존 `delipick_app` / `delipick_server` 구조를 유지했습니다. 추천 가중치와 점수 계산식을 새로 설계하지 않았습니다. 원래 작업 폴더의 미커밋 변경은 그대로 보존했습니다.

| 검증 | 결과 |
| --- | --- |
| 기존 SQL을 새 Docker 볼륨에 가져오기 | 성공: 음식점 66개, 메뉴 1,104개, 리뷰 1,937개 |
| 기존 데이터 Qdrant 구성 | 1,104 points, 재초기화 후 수량 유지 |

| 가상 데이터 Qdrant 구성 | 메뉴 224개 / 224 points |

기계 판독 결과는 이 폴더의 JSON/XML에 있습니다. Android 실기기 설치와 iOS 실행은 이번 검증에 포함하지 않았습니다.

## 발견해서 보완한 부분

1. **네이버 실패 시 시간 덮어쓰기:** API 실패를 임의의 20분으로 저장하지 않도록 바꿨습니다. 기존 시간과 갱신 시각을 유지하고, 인증·할당량 오류는 해당 배치를 중단합니다. 키가 없으면 갱신 작업을 시작하지 않습니다. 최초 갱신도 백그라운드로 실행해 서버 시작을 막지 않습니다.
2. **설정 누락:** 네이버 설정의 API 컨테이너 전달, 검색 후보 수 설정, CORS, 맛 분석 사용 여부를 점검했습니다. DB_NAME을 명시하면 다른 DB로 자동 연결하지 않으며, 직접 실행용 DB_PORT를 지원합니다. 초기화 컨테이너에는 OpenAI 키를 전달하지 않습니다.
3. **불완전한 DB 가져오기:** 시작/완료 상태와 SQL 해시를 기록하고 메뉴·리뷰 등 수량을 확인합니다. 일부만 가져온 DB나 출처 불명의 비어 있지 않은 DB를 정상으로 간주하지 않습니다. SQL 원문은 별도 공유하고, Git에는 모델·차원·해시·예상 수량 메타데이터만 둡니다.
4. **Qdrant 데이터 혼합·잔여 벡터:** 컬렉션 소유 데이터셋, 벡터 차원·이름·유사도 설정, 전체 ID를 검증합니다. 소유 컬렉션에서만 삭제된 ID와 사라진 named vector를 정리합니다. 구형 컬렉션은 SQL과 전체 ID/벡터 대조 후에만 인수합니다.
5. **태그 재초기화:** 자동 생성 태그를 재구성해 오래된 행이 남지 않도록 하며, 수동 태그는 보존합니다.
6. **Flutter 연결·상태:** 기본 에뮬레이터 포트를 18086으로 맞추고, 모든 맛을 중간으로 선택한 값이 미선택으로 바뀌는 문제와 늦은 이전 응답이 최신 결과를 덮는 문제를 수정했습니다. 서버 오류 표시와 개인화 정렬 안내도 보완했습니다.
7. **테스트와 문서:** 기본 counter 테스트를 실제 API 직렬화·UI 상태 테스트로 대체했습니다. 과거 문서의 '핵심 파일 전부 무변경'은 통합 당시 기록이며, 이번에 `main.py`와 `update_delivery.py`에는 위 안전성 수정이 추가됐습니다. 현재 체크섬은 `source_manifest.json`을 기준으로 합니다.

## 해석과 한계

- 새 검증은 외부 OpenAI·네이버 호출을 끄고 replay/모의 응답으로 실행했습니다. 실제 키의 인증 성공, 요금, 외부 API 응답시간은 검증하지 않았습니다. live 사용은 팀원이 자신의 키로 별도 확인해야 합니다.
- 테스트 통과는 기존 계산과의 일관성 및 예외 처리 확인입니다. 사람이 판단한 추천 정확도, 실제 도착시간 정확도, 전국 규모 성능을 증명하지 않습니다. 이전 속도 측정은 `docs/validated_experiments`의 별도 실험 기록입니다.
- replay는 기록된 네 문장용입니다. 자유로운 자연어 입력 시험에는 live 설정이 필요합니다. 메뉴 임베딩 전체를 요청마다 다시 생성하지는 않습니다.
- ETA에는 시뮬레이션과 고정 출발/도착 기준이 있습니다. 실제 사용자 GPS·라이더 배차와 연결된 예측이 아닙니다. 장바구니와 주문 완료는 모의 화면입니다.
- DB 변경을 Qdrant에 계속 동기화하는 운영용 이벤트 처리기는 없습니다. 초기화 시 동기화합니다. 운영 보안, 실기기/iOS, Android 정식 서명도 별도 과제입니다.
- 이번 브랜치의 최신 파일에서는 원본 SQL·수집 JSON·키를 제외합니다. 기존 Git 이력에 이미 있던 데이터를 삭제하는 이력 재작성은 하지 않습니다. 과거 이력의 공개 가능 여부는 별도로 판단해야 합니다.

## 팀원 테스트

`docs/TEAM_TEST_GUIDE.md`의 새 폴더 clone 절차를 사용합니다. 같은 SQL, 같은 입력·맛·유형으로 기존 버전과 비교하고 첫 요청/반복 요청을 분리해 기록합니다. 현재 사용 중인 로컬 컨테이너는 자동 교체하지 않았으므로 수정본 적용 시 시작 스크립트를 다시 실행해야 합니다.
