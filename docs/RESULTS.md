# 테스트 결과

## 검색 성능 (2026-10-19)

동일한 Docker MySQL 데이터에서 기존 계산, 조건 필터 후 전체 계산(SQL), Qdrant를 사용하는 개선 경로를 비교했습니다. 10배·30배 데이터는 기존 데이터의 ID를 바꾸어 복제했습니다.

| 데이터 규모 | 기존 평균 | SQL 평균 | 개선 경로 평균 | 개선 경로 p95 |
| --- | ---: | ---: | ---: | ---: |
| 1배 | 366.69ms | 26.37ms | 28.31ms | 37.11ms |
| 10배 | 6,341.55ms | 182.11ms | 234.60ms | 365.32ms |
| 30배 | 23,166.54ms | 927.24ms | 672.86ms | 927.79ms |

- 국물·면·혼자 먹기 세 질의별 워밍업 1회, 측정 3회로 경로마다 9회 측정했습니다. 워밍업 후 실행 순서를 섞었습니다.
- LLM 분석과 사용자 임베딩은 기록된 응답을 재사용하고 ETA를 고정했습니다. 외부 API 대기시간과 인덱스 생성 시간은 제외한 검색·재정렬 구간입니다.
- 1배의 세 질의는 후보가 200개 이하라 개선 경로에서도 Qdrant를 우회합니다. 구조 개선 전체의 결과이며 Qdrant만의 속도 향상으로 해석하면 안 됩니다. 10배에서는 SQL 경로가 더 빨랐습니다.
- 환경: i7-13700KF, 논리 CPU 24개, Docker 메모리 약 15.52GiB. Python 3.12.15 / MySQL 8.4.11 / Qdrant 1.19.2.

### 결과 유지 확인

같은 조건을 적용한 SQL 전체 계산과 개선 경로를 비교했습니다.

| 검사 | 결과 |
| --- | --- |
| 실제 데이터 파라미터 조합 | 336개 중 순서 일치 336개, 새 빈 결과 0개, 동일 ID 점수 차이 0 |
| 가상 데이터 파라미터 조합 | 576개 중 순서·점수 일치 576개 (점수 허용 오차 1e-9) |
| 인식한 태그·제외 단어·가격·카테고리 조건 | 반환 1,584개 중 위반 0개 |
| 30배 넓은 요청: 6개 질의 × 3개 유형 | 18개 중 결과 수·순위별 메뉴명·점수 일치 18개 (점수 허용 오차 1e-6) |

조합 수는 독립적인 자연어 문장 수가 아닙니다. 기존 예시의 유형·맛·필터 조합을 검사한 것이며, LLM이 놓친 조건이나 사람이 느끼는 추천 정확도까지 검증한 결과는 아닙니다. 복제 데이터는 동점 ID가 달라질 수 있습니다.

### HTTP 동시 요청

실제 데이터 1배 환경에서 각 수준별 32건을 측정했습니다. 외부 분석 결과는 재생하고 ETA는 고정했습니다.

| 동시 요청 | 정상 200 / 5개 반환 | 평균 | p95 |
| ---: | ---: | ---: | ---: |
| 1 | 32/32 | 106.94ms | 357.63ms |
| 4 | 32/32 | 315.57ms | 1,028.57ms |
| 8 | 32/32 | 587.92ms | 1,985.00ms |

기존 API와의 동시 부하 비교는 하지 않았습니다. 짧은 실행 결과이므로 운영 최대 처리량이나 장시간 안정성을 보장하지 않습니다.

## 공유 전 실행 검사 (2026-10-25)

기존 SQL과 가상 데이터를 각각 새 Docker 볼륨에 넣어 초기화·검색·재시작을 확인했습니다.

| 검사 | 결과 |
| --- | --- |
| 기존 SQL | 음식점 66개 / 메뉴 1,104개 / 리뷰 1,937개 / Qdrant 1,104 points |
| 가상 데이터 | 음식점 28개 / 메뉴 224개 / Qdrant 224 points |
| 기존 데이터 Python 테스트 | 72개 통과 |
| 가상 데이터 Python 테스트 | 71개 통과, 실제 데이터 전용 1개 건너뜀 |
| 추천 HTTP 요청 | 환경마다 네 예시 모두 200, 각 5개 반환 |
| Flutter 테스트 / 정적 분석 | 6개 통과 / No issues |
| Android debug APK 빌드 | 성공 |
| Git 공유 파일만 있는 새 폴더 | .env 자동 생성, 가상 데이터 시작 및 추천 정상 |
| 재초기화 / 완료 DB의 SQL 없는 재시작 | 정상, 데이터 수량 유지 |
| 일부만 가져온 SQL / 출처 불명 DB | 실행 중단, 기존 행 보존 |
| Docker 설정 전달 | 11개 설정 전달 확인, 초기화에는 외부 API 키 제외 |

점검 중 네이버 API 실패 시 기존 배달시간을 덮지 않도록 수정했습니다. DB 가져오기 완료 여부와 Qdrant 데이터 소유권·벡터 정합성을 검사하고, 오래된 자동 태그와 벡터를 정리하도록 보완했습니다. 앱에서는 모든 맛을 중간으로 선택했을 때 초기화되는 문제와 이전 응답이 최신 결과를 덮는 문제를 수정했습니다.

이 실행 검사는 외부 OpenAI·네이버 호출을 끄고 진행했습니다. 실제 키 인증, live 자연어 품질, 실기기·iOS는 별도 확인이 필요합니다. ETA는 시뮬레이션이며 실제 주문·결제는 연결되어 있지 않습니다. 실행 방법과 팀원 비교 항목은 [DOCKER_GUIDE.md](DOCKER_GUIDE.md)를 참고하세요.
